# 高德：用户自带 Web 服务 Key

高德接入使用开发者应用的「Web 服务」Key。每个用户可以自行申请并提供自己的 Key。这是妥啦按用户保存调用凭据，不是高德 App 个人账号授权；不读取个人收藏、搜索历史或订单。

官方申请说明：<https://lbs.amap.com/api/mcp-server/create-project-and-key>。

## 客户端

「连接应用 → 高德地图 → 打开连接设置」提供申请教程链接、密码式 Key 输入、验证并连接、替换 Key 和断开连接。Key 只在输入和请求期间保留于内存，不写入手机持久存储，提交后清空；已保存的完整 Key 不回显。

服务器目录必须返回 `credential_scope: "user"`；旧服务器缺少这一标记时，客户端提示升级，不使用旧版公共地图连接。

## 后端

所有接口使用当前会话确定用户，客户端不能指定凭据所有者：

- `POST /v1/integrations/amap/connect`，请求体 `{ "web_api_key": "用户的 Key" }`。实际搜索接口校验成功后，再加密保存。
- `POST /v1/integrations/amap/read`，支持 `search`、`route`、`weather`。只解密并使用当前用户的 Key。
- `DELETE /v1/integrations/amap`，清除当前用户保存的凭据并终止后续读取。

复用 `integration_accounts`，主键为 `(user_id, provider)`。凭据用现有 `CONNECTOR_ENCRYPTION_KEY` 加密，认证数据绑定用户和服务，不能将一个用户的密文挪给另一个用户使用。状态接口仅返回连接状态，不返回 Key 或密文。

继续使用现有跨实例读取限流、并发控制、读取租约与凭据更新代次。替换失败保留原 Key；替换或断开后，旧请求不能将失效连接的响应交还用户。

## 部署与兼容

不新增数据库表，也不设置用户 Key 的环境变量。旧 `AMAP_WEB_API_KEY` 定义只为兼容历史配置保留，地图查询不再读取它，后台页面不再显示该输入项。管理员只需保证用户凭据加密功能可用。

天气查询同样使用当前用户的 Key。旧版客户端升级前可能没有填写入口，需要使用含本改动的新客户端。断开妥啦连接不会删除高德开放平台上的 Key；如需撤销 Key，用户应在高德控制台操作。

验收覆盖：真实地点、路线和天气请求；数据库加密与响应脱敏；两个用户之间的隔离；错误 Key 替换保留原凭据；断开后拒绝查询；旧服务器兼容提示。
