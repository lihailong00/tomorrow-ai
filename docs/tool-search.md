# 按需工具发现（试验开关）

本实现保留现有模型和 Rust 的权限、确认、幂等与取消机制，不添加独立的分类模型请求。`AGENT_TOOL_SEARCH_ENABLED=true` 由部署环境开启，仅影响聊天；默认关闭。请求正文不能打开此策略，后台任务保留原路径。

首次模型请求只看到 `search_tools` 和本轮允许的 `list_memories`、`get_memory`、`list_tasks`、`get_task`，最多五个入口。时间已有可信请求上下文，精确时间工具按需发现。首轮两工具试验显示纯检索会增加简单记忆/待办请求的等待，因此保留这四个常用只读工具。需要业务能力时，模型用自然语言检索；服务端检索本轮 Rust 允许的基础工具和真实已连接账号，返回小型能力摘要，并在下一次模型请求加载相关完整 schema。MCP 工具以稳定别名暴露，执行时映射回原 `call_mcp_tool` 桥接，沿用原操作索引和确认流程。

连接信息和已加载集合仅在当前 run 内缓存，不跨账号或会话共享；普通聊天不查询个人连接。服务说明只用于检索，结果不构成操作授权。不查未连接服务的工具，不猜测远端工具名称，不回传凭据或账号额外字段。原模型可继续按 provider、query 与真实 next_offset 检索目录。

一次运行最多 12 次工具检索，动态集合最多 32 个定义、48,000 字符序列化 schema；远端单个 schema 过大或非 object 时不加载。达到限制不会裁掉 schema 的必要字段或扩大原权限。候选相关性使用名称、说明、中文分词片段和能力词扩展，尚未引入向量模型。个人数据检索优先于内容中偶然出现的商家主题，读请求优先加载读工具。

高德路线增加坐标来源检查：仅接受本轮可信坐标、当前用户明确给出的坐标，或本轮高德地点查询实际返回的位置；不能从其他资料或邮件中的坐标冒充地图查询结果。

运行记录 `started.tool_loading` 标明 `on_demand` 或 `eager`。检索本身也占用工具步数；模型仍需根据实际结果决定是否继续。搜索成功、工具调用成功和业务目标完成是三个不同的验收条件。

测试：在 `services/agent` 运行现有 `test` 命令，已包含 `tool-search.test.ts`。真实 DeepSeek 及外部服务对照的证据保存在忽略目录 `artifacts/tool-search-20261103`。试验结果未完成验收前，不替换线上默认策略或更新 APK。
