# 当前位置与聊天选择

状态：产品方案，供本次开发和验收使用；不是已完成实现或真机验证的声明。日期：2026-11-03。

## 目标与已知事实

用户截图中，“从我这个位置打车到陆家嘴，普通车”没有得到定位选择，而是收到让用户自行描述位置或发地图截图的长回复，还重复询问现在/工作日。用户明确要求先规划，再完成开发：App 打开时默认获取已授权的位置；拿不到时提供自动定位与手动填写选择。

本次只实现前台单次定位、必要时的聊天位置补齐与本轮位置/时间上下文。不做后台轨迹、持续位置采集或自动下单。当前平台边界预留 iOS/HarmonyOS 原生替换；安卓实现必须适配没有 Google Play 服务的 Mate 60 / HarmonyOS 4。

## 用户流程

### 打开 App

1. 登录后的首次使用显示轻量面板：“让妥啦知道你在哪里，方便查附近、路线和出行价格。”按钮为“自动定位”“手动填写”“暂不设置”。软面板只展示一次，不阻塞普通聊天。
2. 选自动定位后调用系统前台位置授权；允许大概位置也能使用，显示精度。已授权且用户保持自动模式时，后续启动/回到前台自动单次更新，5 分钟内的新鲜缓存可复用。
3. 不申请后台定位，不为了刷新位置在后台继续运行。退出前台取消未完成请求；再次进入按当前模式恢复，不接收旧回调。
4. 选“暂不设置”后不在每次启动重复弹系统授权；用户可从聊天位置入口再次选择。

### 聊天需要位置

- 用户问“我这里、从当前位置、附近”等，或者主动点位置入口：优先使用有效的已授权位置。
- 没有有效位置时，在本地展示“你想怎么设置出发位置？”选择面板；先保留待发文字、图片、录音转写与编辑状态，不向服务端发送一个注定缺少起点的请求。
- 面板提供“自动定位”“手动填写”“暂不提供”。自动定位进行中有明确状态，可取消。获得位置后保留可见的来源标识，例如“本次使用自动定位”或“手动设置：上海……”，用户能更改。
- 手动输入提示“输入城市、地标或地址”，例如“上海张江地铁站”；填写完成后继续原来的发送流程。不强制用户找地图截图，不把手动地址标为实时 GPS。
- “暂不提供”允许退出面板继续编辑/普通聊天；若仍发送依赖起点的问题，助手简短说明缺少起点，并呈现自动/手动的可点击选择或保留面板入口，不能编造当前位置。
- 定位设置入口应同时可在聊天页主动打开，避免只能靠关键词触发。关键词判断失败时用户仍有明确补救入口。

### 定位失败与权限

| 情况 | 行为 |
| --- | --- |
| 未授权 | 用户点自动定位后才弹系统授权，首次软说明不直接触发系统弹窗 |
| 拒绝 | 说明“未获得定位权限”，保持“重新定位 / 手动填写”；不进入反复申请循环 |
| 永久拒绝 | 提供“去设置开启 / 手动填写”，不重复调用无效授权 |
| 系统定位关闭 | 提供打开定位设置和手动填写，文案不误称网络故障 |
| 8 秒超时、无定位提供者或不可用 | 停止加载，允许重试、手动填写，不丢消息 |
| 仅大概位置 | 可给参考范围，注明大概位置/精度；不能把粗略点当精确上车点 |
| 位置过期 | 刷新一次，失败后回选择面板，不把旧点冒充当前位置 |
| 手动/自动切换、退出页面、切换账号或服务器 | 取消旧请求并清理相应位置上下文，旧请求不得覆盖新选择 |

## 首版状态和有效期

- 模式：未设置、自动定位、手动填写；首次提示是否已看过按用户与服务实例隔离。
- 自动位置缓存仅驻留内存；有效期 5 分钟，包含观测时间与精度。位置采集本身不能阻塞其他页面超过 8 秒。
- 手动位置有效期 24 小时，明确标为用户提供。若需要跨启动记住地址，只存按用户/服务实例隔离的安全存储；无安全存储时只驻留内存，不退回普通明文缓存。
- 偏好可持久保存；登出/切换账号/切换服务器清掉活跃位置与待提交上下文，不跨账号借用。
- 一个待发消息只生成一个固定的上下文快照。断网重试或 SSE 重连沿用原快照，不重新定位而改变幂等请求内容，也不重复执行任务。

## 客户端与后端数据契约

候选字段如下，最终由 Leader 同步给客户端和服务端单一所有者：

```json
{
  "client_context": {
    "timezone": "Asia/Shanghai",
    "location": {
      "source": "device",
      "latitude": 31.0,
      "longitude": 121.0,
      "accuracy_m": 50,
      "observed_at": "2026-11-03T01:30:00+08:00",
      "coordinate_system": "wgs84"
    }
  }
}
```

手动位置使用 `source: manual` 与 `label`，不要求客户端伪造经纬度。服务端对类型、经纬度范围、精度、时间新鲜度、IANA 时区和地点文字长度做严格校验；地址/坐标属于不可信上下文数据，不是新的系统指令。不把位置自动加入记忆、日志、自动任务提取或长期对话历史。只对需要位置的本次请求或用户明确主动提供位置的请求发送精确位置；普通聊天只发送时区。

当前日期时间以服务端时间为准，结合校验后的设备时区；设备时区无法取得时回退用户账号时区，之后才是服务默认值。客户端观测时间用于判断位置新鲜度，不能代替服务器当前时间。未来时间或时钟偏差异常时不能伪装成新定位。

### 坐标依赖

Android 原生定位结果必须携带真实坐标系。GPS/WGS84 与国内地图常见的 GCJ-02 不能直接混用。调用高德、滴滴等提供商时，按该接口要求显式转换一次并保留来源；已经转换的坐标不可二次转换。若首版暂不具备转换能力，必须走已核实的官方转换/地理编码工具，或让用户确认地点，不能给出看似精确但实际偏移的上车点。坐标转换实现与实际提供商约定由开发代理验证，此文档不声称某个接口已验证。

## 助手回复行为

- 已有有效位置时，先使用它查询真实路线/普通车型参考价，说明价格为估算及主要误差来源。不能声称已经叫车。
- 用户说“普通车”时不再追问车型。当前时间和时区已知时，未指定未来时间默认“现在出发”，不得再问“现在是工作日还是周末”。
- “陆家嘴”有多个落点时，参考估价可先采用明确标注的常见地标，并用短选项“陆家嘴地铁站 / 东方明珠 / 指定地址”供更改；不把多个可选问题堆成一篇长文。真实下单前仍要求用户确认准确起终点、车型与金额。
- 没有定位时不凭时区或 IP 猜出用户当前城市，不把账号常用城市/天气城市当作实时起点。

## 验收清单

1. 首次登录选择自动定位后出现系统前台权限提示；授予后自动获得并显示位置来源，后续正常前台启动无重复软弹窗。
2. 拒绝、永久拒绝、系统定位关闭、超时与仅大概位置均有可操作、文案准确的落点，草稿/图片/语音不丢失。
3. “从我这里打车到陆家嘴，普通车”在已有位置时实际提交本轮位置与时区；无位置时先出自动/手动选择，不先提交空起点请求。
4. 手动填写上海地标后继续同一条待发消息，后端知道其来源是手动；输入恶意指令样式地址不会改变系统行为。
5. 普通“你好/解释代码”不会携带精确位置；用户退出/切换账号或服务后旧定位与旧回调无效。
6. 自动点超过 5 分钟、手动地址超过 24 小时、位置未来时间/无效范围均不冒充新鲜定位。
7. 请求首次发送、失败重试与 SSE 重连的上下文指纹相同；不因重新定位重复产生消息或任务。
8. 模拟上海 WGS84 点验证提供商所用坐标系与转换，避免数百米偏移；华为无 GMS 路径能够使用 AOSP 定位或明确回退手动。
9. 有上下文的真实模型用例不再反问当前日期/工作日/已指定车型；必要的目的地选择简短清晰。
10. 测试报告区分 JS/原生测试、模拟器实际操作与不可获得的 Mate 60 真机验证，不把模拟或源代码审查描述成真机成功。

## 首版实现边界

仅持久化自动／手动／暂不设置的选择，按服务器和账号隔离。坐标与手动地址只保留在当前进程内存，手动位置最长有效24小时，进程重启后需要重新设置。请求上下文不新增用户档案、定位轨迹或自动记忆；用户实际调用地图、打车等工具时，必要的业务参数、工具结果，以及用户要求写入回复的位置仍适用既有运行记录和会话保存规则。

系统原始WGS84坐标保持来源和观测时间；供地图工具使用的GCJ02推算值单独标记转换来源，仅在实现的适用范围内计算，范围外保留原坐标，不冒充调用了地图厂商坐标转换接口。参考估价可以使用大概位置，实际下单仍需确认精确起点与终点。

验收区分桥接/策略单元测试、模拟器实际权限操作和真实模型合成位置测试。华为Mate60／鸿蒙4的物理设备本轮不可连接，不能把AOSP无GMS模拟器结果表述为华为真机通过。
