# 本机资料缓存与增量更新

本流程只在手机内读取系统资料、统一记录格式并加密缓存，不调用模型、不上传资料、不自动创建待办。照片只保存元数据和原图引用，图片理解属于单独授权的流程。

## 触发与展示

- 初次授权建立资料库。之后打开页面或回到前台，直接读取本机缓存，保留已有预览、分页位置和勾选；不因页面挂载重置同步进度。
- Native 模块按已授权来源监听 ContentObserver，合并 1.5 秒内的通知。变化计数持久保存；扫描期间又有变化，完成后继续一次更新。
- 冷启动后的观察空窗、照片授权范围变化、用户主动刷新，以及间隔至少 6 小时的补偿核对，会触发版本/指纹检查。Android WorkManager 的周期执行受系统调度影响，并不保证精确到点。
- 首页只在首次建立资料库时显示明显的导入状态。日常显示“本机已保存 … 条资料”和接下来的安排，后台检查不清空已有结果。

## 增量边界

- 联系人先比对 ID 和 `CONTACT_LAST_UPDATED_TIMESTAMP`，仅对变化的联系人读取完整详情。
- Android 11 及之后的照片先比对 ID、`GENERATION_MODIFIED` 和媒体数据库版本；旧系统比较日期、大小等元数据。不会读取原图像素。
- 短信和日历缺少通用的可靠修改版本号。收到变化或补偿核对时仍要分页比较记录指纹；日历包括参会人、提醒和扩展信息，不能只比较事件 ID。只有新增或变化的记录才重新转换、读取详情或加密写入。
- 完整的一轮身份核对成功后，才清理已经消失的缓存。中途失败保留原缓存和检查点，避免把读取失败当成“全部删除”。
- 这实现的是缓存优先与内容增量处理，并不是所有系统来源都拥有 O(变化条数) 的原生变更日志。数据库 v1 升级保留已有缓存，首次补齐版本指纹可能需要重新读取内容一次。

## 隔离与校验

缓存按服务器、实例和用户隔离。取消来源或撤回权限时清理相应缓存和勾选；退出账号清理本机资料缓存。部分照片权限的预览再次验证当前系统可见范围。用户主动将所选短信/日历交给 AI 前重新读取缓存记录，并再次检查敏感短信及取消日程的限制。

定向验证覆盖缓存复用、变化判断、分页/勾选保留、权限撤回、错误任务停止轮询、敏感短信拦截和原生桥接签名。完整 APK、真机系统通知和 Android 数据库迁移的运行时验收仍需在统一打包时完成。
