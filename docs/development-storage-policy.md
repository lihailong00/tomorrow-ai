# 开发磁盘预算

## 目标与计量

本项目所有本地开发共用 **10 GB（10,000,000,000 字节，约 9.31 GiB）** 项目预算，不能给每个 Agent、工作区或磁盘分别分配 10 GB。预算覆盖常驻文件和构建、安装、测试过程的临时峰值。

计入：项目源码及 Git 元数据、各工作区的项目依赖、Rust `target`、项目可归属的依赖缓存、Android 构建输出、项目专用 Docker 镜像及缓存、模拟器副本、测试数据、日志、报告和历史安装包。放在仓库之外的项目文件同样计入。共享目录不得重复计数，也不得直接当作零占用；无法确认归属的空间必须单独报告，不能据此宣布达标。

已经安装、供多个项目共用的 Android SDK / NDK、JDK、Rust 工具链及原始模拟器环境单独统计，不包含在上述项目预算中。因此，本规范不代表整台电脑的开发环境只占 10 GB；若把公共工具也纳入上限，需要另行核对可行性，不能依靠挪动目录或省略统计宣称达标。

文件长度可用于保守预算；报告要注明统计口径。硬链接不应重复计入实际占用；稀疏镜像应区分文件长度和实际分配空间。Docker 内部空间和其虚拟磁盘不得相加。

## 每次开发的执行规则

1. 安装、编译、原生测试和大文件生成前，核对所有项目工作区、临时目录及项目专用外部缓存的用量，记录当前用量与预计峰值。
2. 达到 9 GB 时预警。预计峰值或收尾占用会超过 10 GB 时，先整理确认无用的产物，或使用已获授权的远程构建环境；仍需超额时先报告原因、预计峰值和收尾方案，不默认沿用此前对 5 GB 目标的放宽。不能为凑数字删除必要数据。只在运行前、运行后检查不能保证过程中不超限。
3. 共享兼容的依赖缓存，指定一个本地构建工作区。共享构建输出只允许一个写入者，避免多个 Agent 并发编译产生重复文件或互相清理。
4. Rust 紧预算构建优先关闭调试符号和增量编译；这些选项会降低调试便利和重复编译速度，且不保证完整构建一定能放进 10 GB。完整验证放不下时，使用已获授权的远程环境，不能省略验证后宣称完成。
5. 原生测试复用受控模拟器，不复制系统镜像或用户数据盘保存证据。优先保存必要的截图、结构化结果和有大小上限的日志。
6. 安装包保留目标是最新版本与一个验收过的回退版本，其他测试报告优先保存小型摘要、版本和校验值。固定入口 `latest` 必须保留并能验证为最新版；兼容别名的额外副本也计入预算。
7. 打包收尾是必做步骤：先校验新 APK 的真实版本、hash 和 latest 固定入口，再保留新最新版及一个验收过的回退版本；清理已确认无用的临时打包文件、旧生成包和不再需要的可重建缓存，复测收尾用量。打包失败时保留此前可用的 latest 和回退版本。活动任务占用、归属不明或必要的验收文件不自动删除。
8. 每次重操作结束记录实际峰值或注明峰值未测量，并记录收尾后的用量。超过预算必须明确报告，不能仅凭“已经清理”宣布符合预算。

## 清理边界

只清理能够确认归属、没有活动任务占用且可以重建的文件。删除前检查解析后的绝对路径，并核对当前任务、构建进程和保留清单。不能一边编译一边删除共享缓存。

源码和未提交修改、数据库、用户上传、密钥、证书、签名材料、最新和回退安装包、必要的验收证据不属于自动清理对象。禁止对共享 Docker 环境直接执行全局 prune，禁止为满足预算把文件搬到另一个未计量目录。

## 当前落地状态

2026-11-01 清理前，各项目工作区文件长度合计约 215.2 GiB，其中 Rust 编译目录约 86.1 GiB。已按逐项审核清单移除可重建缓存、模拟器副本、旧 APK、旧生成程序和部署包，并复测保留文件。

清理后，原工作区合计约 8.27 GB，另有仓库外专用路径约 0.34 GB，合计约 **8.61 GB（8.02 GiB）**，低于现在采用的 10 GB 项目路径预算。这一保留基线包含源码、依赖、测评数据、历史验收资料、私有配置/数据、最新及回退安装包；本次没有为了达到目标继续删减这些内容。共享 SDK、工具链、Gradle/Cargo 缓存与 Docker 状态另外报告，不能把 8.61 GB 宣称为整台电脑全部开发空间。

`scripts/Build-Android.ps1` 已接入自动检查与清理，默认无需额外开关：

1. 取得所有关联工作区共用的打包锁，统计 Git 工作区、公共 Git 元数据、登记的外部路径；嵌套路径不重复计数。使用文件长度保守计量，硬链接可能多计；链接目标已位于统计路径内时视为已计入，否则报告统计不完整。读取失败也会明确报告。
2. 9 GB 预警，构建前按默认 2 GB 预计增量评估临时超额风险；可通过 `-EstimatedBuildBytes` 调整预估。空间紧张时先清理当前工作区确认可重建的缓存。构建磁盘剩余空间不足预计增量时停止；10 GB 目标采用尽力控制和超额告警，不将预估当实测，也不静默删必要资料。
3. 发布由 `scripts/Publish-AndroidApk.ps1` 在输出目录锁内完成，校验真实包名、版本与 SHA256；latest、兼容别名、回退包、元数据失败时一起恢复。`tada-rollback.apk` 保存原 latest；相同内容重发不轮换回退。旧 schema 首次升级仅从可验证且至少一小时以前的较低版本生成包补齐回退。
4. 校验发布完成后，删除本输出目录中可识别且版本更低的旧生成 APK。上一版已提交来源在验证与回退包或新 latest 的哈希一致后可立即删除冗余副本，即使重复打包沿用相同 versionCode 也不会一直累积已提交旧来源；其他旧包保留一小时宽限，防止误删等待发布的输入。自定义、无效、其他应用、同版本或更新版本、被占用文件保留并记录。崩溃留下或归属不明的 `.apk-publish-*` 恢复材料不自动猜测删除。
5. 构建结束（成功或失败）清理当前工作区固定的 Android `app/build`、`build`、`app/.cxx`、`.gradle` 目录；空间紧张时可清理有 `CACHEDIR.TAG` 的当前 Rust `target`。存在活动构建进程、跟踪的源码、数据库、密钥、无法读取的条目或链接则跳过整项目录。外部原生缓存仅在脚本创建了匹配工作区和绝对路径的归属标记时可清理；不删除其他工作区或共享 Docker/依赖缓存。
6. 收尾复测，并覆盖写入 `artifacts/packaging-storage.json`，不无限累积报告。失败也尝试清理和记录，但清理失败不会覆盖构建的原始错误。仍超额或统计不完整时明确警告。

`.tada-storage.local.json` 是被 Git 忽略的本机统计清单，格式如下；`additional_measure_paths` **只扩展统计范围，绝不扩展删除权限**。脚本会自动登记当前指定的原生缓存、`CARGO_TARGET_DIR` 和 `GRADLE_USER_HOME`，历史路径仍保留计量。

```json
{
  "schema_version": 1,
  "additional_measure_paths": ["D:/tada-native-build"]
}
```

**没有设置操作系统硬配额，也没有持续监控构建峰值**。报告中的峰值实测为空，单独记录预计增量。共享 SDK、工具链、全局依赖缓存和 Docker 的项目归属仍需另外核对，不能把文件路径统计宣称为整台机器的完整用量。历史手动清理清单、前后统计与校验保存在主项目 `artifacts/storage-cleanup-20261101/`。
