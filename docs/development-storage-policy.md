# 开发磁盘预算

## 目标与计量

本项目所有本地开发共用 **20 GB（20,000,000,000 字节，约 18.63 GiB）** 收尾保留空间上限，不能给每个 Agent、工作区或磁盘分别分配 20 GB。按照用户 2026-11-02 的最新要求，**编译速度优先，超过上限也必须等编译结束后才能清理**。实际磁盘空间充足时允许构建、安装和测试临时超过 20 GB，不为此中断编译、预先清缓存、关闭增量编译或反复请求例外。构建结束（成功或失败）后再计量；仅在保留量超过 20 GB 时自动安全清理，未超限保留可复用缓存。显式请求的构建后清理仍可使用。

20 GB 是收尾上限，不是操作系统磁盘配额。若保护数据或活动/未知归属缓存使安全清理后仍超过上限，必须报告“未满足收尾上限”；统计不完整则报告“无法确认达标”，不能把编译成功或已执行清理当作空间达标。

计入：项目源码及 Git 元数据、各工作区的项目依赖、Rust `target`、项目可归属的依赖缓存、Android 构建输出、项目专用 Docker 镜像及缓存、模拟器副本、测试数据、日志、报告和历史安装包。放在仓库之外的项目文件同样计入。共享目录不得重复计数，也不得直接当作零占用；无法确认归属的空间必须单独报告，不能据此宣布达标。

已经安装、供多个项目共用的 Android SDK / NDK、JDK、Rust 工具链及原始模拟器环境单独统计，不包含在上述项目预算中。因此，本规范不代表整台电脑的开发环境只占 20 GB；若把公共工具也纳入上限，需要另行核对可行性，不能依靠挪动目录或省略统计宣称达标。

文件长度可用于保守预算；报告要注明统计口径。硬链接不应重复计入实际占用；稀疏镜像应区分文件长度和实际分配空间。Docker 内部空间和其虚拟磁盘不得相加。

## 每次开发的执行规则

1. 安装、编译、原生测试和大文件生成前，核对所有项目工作区、临时目录及项目专用外部缓存的用量，记录当前用量与预计峰值。
2. 开始前检查实际磁盘剩余空间是否足以容纳预计增量。空间充足时直接编译，不因预计临时用量超过 20 GB 而阻断、反复请示或触发预先清缓存。实际空间不足时停止并说明需要的空间，选择可容纳构建的路径或已获授权的远程环境；不能为凑数字删除必要数据。
3. 共享兼容的依赖缓存，指定一个本地构建工作区。共享构建输出只允许一个写入者，避免多个 Agent 并发编译产生重复文件或互相清理。
4. 构建配置优先考虑执行速度和可复用缓存，不为临时符合 20 GB 而默认关闭增量编译或反复重建依赖。共享输出保留单一写入者；需要并行工作时明确各自输出的归属。实际磁盘空间无法容纳验证时，使用可容纳的已获授权环境，不能省略验证后宣称完成。
5. 原生测试复用受控模拟器，不复制系统镜像或用户数据盘保存证据。优先保存必要的截图、结构化结果和有大小上限的日志。
6. 安装包保留目标是最新版本与一个验收过的回退版本，其他测试报告优先保存小型摘要、版本和校验值。固定入口 `latest` 必须保留并能验证为最新版；兼容别名的额外副本也计入预算。
7. 打包收尾检查是必做步骤：先校验新包的真实版本、hash 和 latest 固定入口，保留最新及一个验收过的回退版本。构建结束后计量，超过 20 GB 才自动清理确认无用的可重建缓存；未超限保留暖缓存。旧生成包按发布保留规则处理。清理后复测用量；失败时保留此前可用的 latest 和回退版本。活动任务占用、归属不明或必要的验收文件不自动删除。
8. 每次重操作结束记录实际峰值或注明峰值未测量，并记录收尾后的用量。收尾仍超过 20 GB 上限时统一报告保留量、原因及跳过的活动或必要数据，不为已经允许的临时峰值重复请求例外，也不能仅凭“已经清理”宣布达标。

## 清理边界

只清理能够确认归属、没有活动任务占用且可以重建的文件。删除前检查解析后的绝对路径，并核对当前任务、构建进程和保留清单。不能一边编译一边删除共享缓存。

源码和未提交修改、数据库、用户上传、密钥、证书、签名材料、最新和回退安装包、必要的验收证据不属于自动清理对象。禁止对共享 Docker 环境直接执行全局 prune，禁止为满足预算把文件搬到另一个未计量目录。

## 当前落地状态

2026-11-01 清理前，各项目工作区文件长度合计约 215.2 GiB，其中 Rust 编译目录约 86.1 GiB。已按逐项审核清单移除可重建缓存、模拟器副本、旧 APK、旧生成程序和部署包，并复测保留文件。

清理后，原工作区合计约 8.27 GB，另有仓库外专用路径约 0.34 GB，合计约 **8.61 GB（8.02 GiB）**，低于当时的 10 GB 旧目标。这一保留基线包含源码、依赖、测评数据、历史验收资料、私有配置/数据、最新及回退安装包；本次没有为了达到目标继续删减这些内容。共享 SDK、工具链、Gradle/Cargo 缓存与 Docker 状态另外报告，不能把 8.61 GB 宣称为整台电脑全部开发空间。

`scripts/Build-Android.ps1` 已接入自动检查与清理，默认无需额外开关：

1. 取得所有关联工作区共用的打包锁，统计 Git 工作区、公共 Git 元数据、登记的外部路径；嵌套路径不重复计数。使用文件长度保守计量，硬链接可能多计；链接目标已位于统计路径内时视为已计入，否则报告统计不完整。读取失败也会明确报告。
2. 构建前记录用量，以默认 2 GB 预计增量检查实际磁盘剩余空间；可通过 `-EstimatedBuildBytes` 调整预估。临时超过 20 GB 不触发构建前清理或预算预警，不额外扫描同一份未变化的构建前用量。实际磁盘剩余空间不足预计增量时停止并保留现有交付物。临时峰值允许超过收尾目标，预估不当作实测。
3. 发布由 `scripts/Publish-AndroidApk.ps1` 在输出目录锁内完成，校验真实包名、版本与 SHA256；latest、兼容别名、回退包、元数据失败时一起恢复。`tada-rollback.apk` 保存原 latest；相同内容重发不轮换回退。旧 schema 首次升级仅从可验证且至少一小时以前的较低版本生成包补齐回退。
4. 校验发布完成后，删除本输出目录中可识别且版本更低的旧生成 APK。上一版已提交来源在验证与回退包或新 latest 的哈希一致后可立即删除冗余副本，即使重复打包沿用相同 versionCode 也不会一直累积已提交旧来源；其他旧包保留一小时宽限，防止误删等待发布的输入。自定义、无效、其他应用、同版本或更新版本、被占用文件保留并记录。崩溃留下或归属不明的 `.apk-publish-*` 恢复材料不自动猜测删除。
5. 构建结束（成功或失败）后先计量，只有保留量超过 20 GB 才自动清理当前工作区固定的 Android app/build、build、app/.cxx、.gradle 目录；未超限保留暖缓存。仍超限时可清理有 CACHEDIR.TAG 的当前 Rust target，传入 -PreserveRustTarget 则保留它。存在活动构建进程、跟踪源码、数据库、密钥、不可读条目或链接则跳过，不在编译中途清缓存。外部原生缓存须有匹配工作区和绝对路径的归属标记；不清理其他工作区或共享 Docker/依赖缓存。共享清理函数拒绝 Preflight，只接受明确的 Success/Failure 后置阶段。
6. 收尾复测，并覆盖写入 `artifacts/packaging-storage.json`，不无限累积报告。报告声明 20 GB 为收尾上限、允许临时超额、构建前不清理。失败也尝试清理和记录，但清理失败不会覆盖构建的原始错误。收尾仍超目标或统计不完整时明确报告。

`.tada-storage.local.json` 是被 Git 忽略的本机统计清单，格式如下；`additional_measure_paths` **只扩展统计范围，绝不扩展删除权限**。脚本会自动登记当前指定的原生缓存、`CARGO_TARGET_DIR` 和 `GRADLE_USER_HOME`，历史路径仍保留计量。

```json
{
  "schema_version": 1,
  "additional_measure_paths": ["D:/tada-native-build"]
}
```

**没有设置操作系统硬配额，也没有持续监控构建峰值**。报告中的峰值实测为空，单独记录预计增量。共享 SDK、工具链、全局依赖缓存和 Docker 的项目归属仍需另外核对，不能把文件路径统计宣称为整台机器的完整用量。历史手动清理清单、前后统计与校验保存在主项目 `artifacts/storage-cleanup-20261101/`。
