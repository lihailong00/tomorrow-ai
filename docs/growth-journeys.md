# 我的成长：连续旅程首版

入口统一进入“我的成长”。未开始时选一个具体目标和每日时间，明确开启后才准备路线；页面进入、刷新、计时和查看历史不调用模型生成。

## 用户流程

1. 选择学习、活动或生活计划，填写目标，选择5／15／30分钟（保留已有自定义时长）。
2. 后端创建持久的 `growth_journey` 任务，当前配置的模型生成3至6个相连步骤，每步包含可确认的完成标准。失败明确展示，最多2次模型尝试和4次调度；24小时内最多开始3段旅程。
3. 首屏只显示当前步骤。开始后得到普通待办；在事项或成长页面打开的是同一条记录。后续步骤需完成或明确跳过前一步才可开始。
4. “AI陪我做”把用户目标、当前步骤和完成标准带入对话。“太难了”请求先拆成5分钟的小练习；不会擅自完成待办。完成后的难度反馈持久保存，并提供给每日建议模型。
5. 成长旅程待办提供本机专注计时；计时结束不记录完成或活动时长。成果和用户笔记从实际确认的待办中回看。撤销完成会同步纠正路线和成长记录。
6. 历史支持本周、本月、全部，30条一页，统计覆盖整段时间。分享先预览，默认只含统计；可明确附上当前页成果标题，私人笔记不进入分享。
7. 成长收藏保留原规则，新增完成旅程的里程碑及Lv.5星光光环。纯跳过路线不解锁“第一段旅程”。

## 数据和接口

新增幂等迁移 `016_growth_journeys.sql`（SQLite和PostgreSQL）；现有待办、成长奖励和生成队列继续复用。成长值仍按现有服务端规则结算，跳过、反馈、计时和生成路线不奖励成长值。

- `GET/POST /v1/growth/journeys`：当前及最近20段历史旅程／开始目标。
- `POST /v1/growth/journeys/{id}/commands`：归档或明确重试，使用版本号和幂等请求号。
- `POST /v1/growth/journeys/{id}/steps/{step}/start`：幂等创建或读取已有待办。
- `POST /v1/growth/journeys/{id}/steps/{step}/commands`：跳过或难度反馈。
- `GET /v1/growth/history?period=week|month|all&offset=0&limit=30`：分页成果与同期统计。

旅程集合只返回待办的必要摘要，移除草稿、资料摘录和私人进度笔记；完整笔记只在用户自己的待办或成果记录中读取。查询和操作均按账号范围隔离。

## 发布衔接

这次修改限于本地代码和验证，未修改云端或APK入口。发布时需要**同时更新Rust API和Worker**，运行新迁移，再发布手机端。Pi/harness和模型厂商配置无须切换。只更新API而保留旧Worker，会使新任务无法准备路线。

模型生成使用当前服务器配置并记入todo用量，不自动切换厂商，不因轮询或重试读取而再次计费。每日建议识别当前旅程，不再为同一方向重复推荐未接纳的新任务；已经接纳的待办保持可见。

首版保留明确边界：AI陪练通过现有对话完成，不是后台自动执行；路线不会凭练习勾选宣称用户掌握技能。不提供排行榜、体力、虚构能力分数或强制连续签到。
