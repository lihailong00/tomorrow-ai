# 每日成长

每日成长建立在个人 Todo 之上，首次默认关闭，没有演示任务、虚构完成记录或初始经验。用户开启后选择学习、活动或生活目标、每日时间，并决定是否让模型参考已保存的待办。官方服务与自建服务使用当前后台的有效模型配置；推荐是只读文本生成，不通过 Pi 执行外部工具。

## 每日计划

`GET /v1/daily-plan` 只读取。`POST /v1/daily-plan/ensure` 明确将当天计划放入持久队列，正常重复请求不会再生成。客户端提交稳定 `client_request_id`，同一请求即使在生成失败后重放，也只返回当前计划，不隐式消耗第二次模型尝试；用户明确重试须使用新编号。用户 IANA 时区决定日期；计划建立后固定其日期与时区，短时间改变用户时区不会额外创建另一份当地日计划。

Worker 在当地时间早上 8 点后分批为开启且最近七天使用过功能的用户准备建议。有界游标每次处理最多 100 个用户，下一批继续推进；本地 worker 每 15 秒检查一批，不阻挡原有队列的两秒轮询。用户首次开启或打开页面也可明确入队，不依赖手机常驻后台。

队列只保存计划编号。模型请求前重新读取当前偏好及拥有的最多 20 条有效 Todo，仅带标题、必要的最多 300 字说明等有限上下文；草稿、原始来源摘录与进度笔记不发送。停用、休息或撤销待办使用权限会阻止旧队列快照发送。生成结果发布还要匹配任务租约、尝试、计划及偏好版本；设置或日期变化时不覆盖用户数据。

模型只输出结构化候选，最多六条，其中最多三条按时间预算展示，其他用于同批替换。引用的已有 Todo 必须来自授权输入且仍属于当前账号，其标题、来源和状态以真实 Todo 为准。新建议仅围绕明确目标，接受后才创建 `source_kind=ai_daily` 的 Todo，不伪装为手动输入或邮件原文。生成成功不会创建完成事实，也不会获得成长值。

模型调用发生前有持久预留，同一任务尝试只调用一次。每份计划最多两次真实模型尝试；失败不走通用任务的自动三次重试，用户可在 `can_retry` 允许时明确重试。派发另有八次上限，暂停等尚未发出模型请求的情况不会消耗两次模型额度。过期租约不开始模型调用，已开始后被回收的未知结果不会盲目再付费。替换只取同批备选，不再调用模型。

生成终态清除持久上下文中的原始待办和目标文本，仅保留必要的预算、版本和日期信息。删除 Todo 同时清理关联显示内容与命令缓存正文，保留身份墓碑，避免删除后重放请求重新创建。发布事务还要与原始持久上下文一致；删除来源导致上下文失效后，即使模型仅返回目标建议，也不能重新落库。

## 成长与真实动作

成长值由服务器固定计算，基础 10 点，每天最多一条重点事项可获得 20 点；60 点一级，新用户从 0 点 Lv.1 开始。奖励与 Todo 状态、明确动作事实和精简成长事件处于同一数据库事务，失败一起回滚。

同一逻辑 Todo 只有一份长期权益。重复请求、后来关闭已回复事项、反复完成，都不产生第二份奖励。撤销完成会修正资格，再完成只恢复原始点数与首次日期、时区；重点额度不会因为撤销被释放给另一件事再领取。关闭功能保留账本并允许纠错，不追溯此前已经完成的 Todo，也不为关闭期间的新完成补发奖励。

`POST /v1/todos/{id}/actions` 使用当前 Todo `version` 和稳定的 `client_request_id`：

- `replied`：用户确认实际回复，父 Todo 进入 `waiting`，回复事实可以获得一次奖励。打开分享、生成草稿或普通 PATCH 为 waiting 都不代表已回复。
- `undo_replied`：纠正回复事实。等待中的事项回到 pending；若另有有效的 completed 事实则保留父状态与奖励资格，不抹去独立事实。
- `exercise_completed`：用户确认活动完成，可提交 `actual_minutes`（未知为 null，已知须为 1–360 的整数）和进度笔记。周统计不从自由笔记、AI 文本或预计时长推断实际分钟。

回复动作的 `draft` 与活动动作的 `progress_notes` 保留三态：省略保持原内容，显式 null 清除，字符串更新内容。清空后确认动作，不会恢复旧草稿或笔记文本。

普通 Todo 完成仍通过版本化 PATCH。`GET /v1/growth/todos/{id}` 提供稳定奖励编号、Todo 编号、active、点数、版本及首次日期，供客户端关联本次操作的权威反馈；不能只比较全局总分变化，误把另一台设备的动作当成本次奖励。旧请求重放是业务无操作，但响应重新读取当前状态，不把已撤销的事项退回旧缓存状态。

## 页面与接口

偏好：`GET/PATCH /v1/growth/preferences`，支持开启、目标、每日时间、已有 Todo 授权、今日休息和已解锁光环。修改携带设置版本，目标与授权变更会使正在生成的结果不能直接应用。

汇总：`GET /v1/growth/summary` 返回真实总成长、等级、今日、本周和里程碑。周记录最多显示 100 条，计数与总分钟由全量 SQL 聚合计算，不能把预览数量当总量。

候选操作：`POST /v1/daily-plan/items/{id}/accept|skip|replace` 携带候选版本和稳定请求编号。接受与新 Todo 插入原子提交，跳过或休息不删除已有待办，已开始的 Todo 不会被替换。未接纳的过期建议不能继续接受；此前已接纳的 Todo 正常保留。

本版本不增加任务商店、排行榜或自动外发功能。未授权手机资料不参与推荐；客户端的模拟交互数据不会进入生产数据库。
