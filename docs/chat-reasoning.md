# 对话思考强度

输入框上方的“思考”按钮提供关闭、轻度、深度、最强四档，对应 `off / low / high / max`。
新建对话默认 `off`；选择保存在当前导航会话中，返回该会话时保留，不作为其他新对话的全局默认。
文字和按住说话共用选择。生成过程中可以修改下一次发送的档位，已经发送的请求与重连、重试继续使用原档位。

## 请求与兼容

`POST /v1/chat`、`POST /v1/chat/stream` 接收可选的 `reasoning_effort` 字段。
只接受上述四个值；缺省等同 `off`。缺省和显式 `off` 序列化为同一请求指纹，兼容此前的持久化重试。
同一 `client_request_id` 改变强度会返回冲突，不能借重试重复执行工具。

Rust 将档位传到 Pi 的 `/v1/runs`。Pi 的 Agent 为整个工具循环固定 `thinkingLevel`。
Rust 直连模式也使用同样的字段；其他后台功能原有的直连调用保持不变。

本版验证的模型是官方 `https://api.deepseek.com`（含 `/v1`）的 `deepseek-flash` 和 `deepseek-v4-pro`。
专用 `DEEPSEEK_*` 和指向官方地址的通用 `MODEL_*` 配置均支持。
其他模型或代理不推定兼容；明确选择思考时返回不支持提示，不能悄悄忽略选择。

关闭时发送 `thinking.type=disabled`；其余发送 `thinking.type=enabled` 和精确的 `reasoning_effort`。
为思考留出有界生成空间：`off=4096 / low=8192 / high=16384 / max=32768` 个输出 token。
输出额度并非已发生费用或保证会用满的数量。直连思考请求使用现有 Agent 的 20 分钟执行上限。
工具循环需要的 `reasoning_content` 由 Pi 在单次运行的内存中回传，不进入公开文字流或事件记录。

## 验证与发布

- 手机组件测试覆盖默认、四档选择、保留会话、切换对话、生成中切换及请求不可变。
- Rust API 的真实本机 HTTP 测试覆盖 JSON/SSE 到 Pi 的参数传递、缓存重放、改变档位冲突和非法参数。
- Pi 安装包的真实请求构造器验证四档上游 JSON；合成 SSE 验证思考和工具循环的衔接与隐私边界。
- Rust 直连测试验证普通和流式请求的序列化参数，并回归已有模型与 SSE 测试。

这些验证不调用付费模型。上线需要同时发布 Rust API、Pi 服务与新 APK；只有源码修改不改变云端或现有 APK。
