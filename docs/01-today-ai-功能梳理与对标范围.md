# Today.ai 功能梳理与对标范围

版本：v0.5（Android 首发，Rust 业务后端 + TypeScript / Pi 执行服务）
调研日期：2026 年 10 月 26 日  
拟建产品：Tomorrow AI（暂名）  
本期平台：仅 Android 手机 App；为后续 iPhone / iOS、原生 HarmonyOS 迁移预留架构  
已确定后端：Rust 业务后端 + TypeScript / Pi Agent 执行服务；手机端继续采用共享客户端与平台适配架构
关联文档：[技术路线与实施计划](./02-tomorrow-ai-技术路线与实施计划.md)

## 1. 先看结论

Today.ai 的产品重心是把「了解用户的长期记忆」「合适时机的主动帮助」「能够完成工作的任务执行」组合成一个个人助手。官网同时展示云端计算机、跨设备操作和社区 Skills。[Today 官网](https://today.ai/)

要做一个体验接近的产品，建议对齐四个层次：

1. **产品结构**：每日首页、对话、任务、记忆、能力与连接。
2. **使用闭环**：记住背景 → 获取新信息 → 提出建议 → 经授权执行 → 回报结果。
3. **连续性**：换会话、App 退出或手机切到后台后，云端任务和用户背景仍然能够延续。
4. **控制感**：用户能看懂信息从哪里来、系统准备做什么，以及如何修改、停止和删除。

本稿保留 Today 的完整公开功能地图作为参考，**本项目当前只交付 Android 手机 App 及其云端服务**。Android 首版完成核心闭环；后续迁移目标为 iPhone / iOS 和原生 HarmonyOS。首期建立可复用的界面、业务与接口层，不把其他客户端的正式发布计入当前排期。功能与交互采用自主实现；产品名称、品牌素材和文案另行设计。

后续所称“鸿蒙”按需要独立适配的原生 HarmonyOS 路线设计；不能以部分历史设备能运行 Android 应用代替鸿蒙迁移。具体版本、机型与能力在迁移验证时锁定。

**已确定的实现约束**：核心云端业务接口、权限、审批、数据与持久任务调度使用 Rust，采用 Axum / Tokio 与可选 Temporal Rust SDK；Agent 模型与工具循环使用独立的 TypeScript + Pi 服务。数据仍使用 PostgreSQL / pgvector、S3 兼容存储，本机体验保留 SQLite / 本地存储。手机端保持 React Native + TypeScript，Android 系统能力使用 Kotlin，未来 iOS / 鸿蒙分别适配。

**当前已实现的 Agent 范围**：对话可通过 Pi 实际查询、保存、修改和删除记忆，创建待确认任务、创建未启用计划草稿、暂停计划及读取文本附件。Rust 强制审批、账号隔离和操作防重。跨外部服务操作、浏览器执行、任意 Skills 等仍属于后续范围，完整边界见 [Pi 服务说明](../services/agent/README.md)。

**选型偏好**：业务实现与接入组件优先采用适合本项目的 Rust 生态方案，同时按平台能力、稳定性和维护成本选择客户端与基础设施。已复核 Rust UI、ORM、向量服务、浏览器和存储候选；Android 首发及未来 iOS / 原生鸿蒙迁移要求保持不变，具体取舍记录在技术文档第 15 节。

### 3.1 连接器目录的正确理解

本次逐项整理的官方目录共 **55 项，其中 17 项明确标注 Soon，38 项未标 Soon**。这表示目录中的展示状态；未标 Soon 仍需逐个验证认证、读取、写入和可用地区，不能直接算作 38 个完整可用连接器。[官方集成目录](https://today.ai/articles/integrations)

目录基线如下，分组仅用于本项目规划：

| 分组 | 未标 Soon 的项目 |
| --- | --- |
| Google / Microsoft | Gmail、Google Calendar、Google Drive、Google Contacts、Microsoft 365、Excel |
| 消息与社交 | Slack、Discord、X、LinkedIn |
| 笔记与任务 | Notion、Todoist、Trello、Asana、ClickUp、Airtable、Linear |
| 会议、文件与设计 | Zoom、Calendly、Cal.com、Dropbox、Miro、Figma |
| 研发 | GitHub、GitLab、Sentry、Supabase |
| 客户与财务 | HubSpot、Attio、YNAB、QuickBooks、Zoho Invoice、Splitwise |
| 健康设备 | WHOOP、Oura、Garmin、Fitbit、COROS |

**标 Soon 的 17 项**：Feishu、Lark、DingTalk、WhatsApp、Reddit、Instagram、Facebook、TickTick、Monday.com、Jira、Tencent Docs、Gong、Salesforce、Dynamics 365、Stripe、Square、Strava。[目录及状态](https://today.ai/articles/integrations)

目录还声明了本机资料、屏幕与电脑操作、剪贴板/脚本、位置与系统信息、通知/使用情况/短信通话等设备能力。应逐平台与分发版本验证，不能把跨端展示推导成每端都能操作任意应用。[设备能力目录](https://today.ai/articles/integrations)

对标时应为每个连接器维护独立的能力卡：

| 字段 | 示例 |
| --- | --- |
| 授权范围 | 日历读取、创建事件分别开通 |
| 可读内容 | 指定日历、指定文件夹或指定消息频道 |
| 可写动作 | 创建草稿、创建事件、更新文档分别定义 |
| 触发机制 | 定时同步、Webhook、手动刷新 |
| 故障状态 | 授权失效、限流、需要用户重新登录 |
| 用户控制 | 停止同步、撤销权限、删除已同步内容 |

我们建议首批打通 Gmail、Google Calendar、Google Drive 三项，形成真实使用闭环；再接 Outlook、OneDrive、Notion、Slack 等。面向国内用户时，飞书、钉钉等应进入单独的接入计划。

### 3.2 录音功能的已知边界

官方 2026 年 9 月 18 日产品文章说明：录音采集先支持 Mac 和 iPhone，摘要及追问可跨支持的平台继续；会前提醒需要用户点击才开始录音。该文章还明确指出，**声纹识别当时处于内部测试，尚未提供自动行动建议**。[Recording 发布说明](https://today.ai/articles/blog/introducing-today-recording)

因此，本项目的录音对标应先完成「用户启动录音 → 转写 → 有背景的摘要 → 原文定位 → 继续追问」。自动生成并执行会后任务属于后续可选增强；若要追求当前版本逐项一致，需再用实际账号确认上述状态是否已更新。

## 5. 拟建产品的信息架构

下面是 Android 手机 App 的界面结构。Today、Tasks、Memories、Capabilities 等入口名称来自官网演示；手机导航、分层和具体交互为本项目建议。[官网演示](https://today.ai/)

| 页面 | 用户进入后要解决的事 | 核心交互 |
| --- | --- | --- |
| 登录与首次设置 | 建立账号，让助手知道先帮什么 | 邮箱等基础登录、语言与时区、目标选择、可跳过的连接与权限步骤 |
| Today / 每日首页 | 迅速知道今天值得关注什么 | 简报、优先事项、建议卡、继续任务、快捷输入 |
| 对话工作区 | 提需求、补充材料、跟进工作 | 流式对话、短语音、相机/相册/文件、来源、任务进度、结果预览 |
| Tasks / 任务中心 | 查看正在进行与自动执行的工作 | 状态筛选、计划暂停/恢复、任务取消、补充信息、确认动作、运行历史 |
| Memories / 记忆中心 | 知道助手记住了什么 | 按人物/项目/偏好等查看，来源、修改、删除、停止记忆 |
| Capabilities / 能力中心 | 配置助手能接触和执行的工作 | 连接器、Skills、权限、状态与重连 |
| 成果与资料 | 找回已经整理的内容 | 文件、报告、引用、版本、下载、继续编辑 |
| 会议记录 | 从记录回到项目进展 | 音频、时间戳转写、摘要、决策、未确认信息、追问 |
| 设置 | 管理个人体验和数据 | 通知权限、静默时间、数据导出与删除、当前设备、套餐用量 |

采用手机纵向单列：底部固定导航提供「今日 / 任务 / 记忆 / 能力」，对话入口位于导航上方；进入聊天或详情页时隐藏主导航，从今日及任务进入对话与成果详情，设置由头像进入。视觉以 [Today 官网演示](https://today.ai/) 的浅色、淡蓝与杏色渐变为主，参考 [华为小艺新版首页](https://consumer.huawei.com/cn/support/content/zh-cn16034494/) 的移动端输入布局与 [简报展示](https://consumer.huawei.com/cn/mobileservices/celia/) 的内容层级。图标、品牌与文案自主实现。使用细线图标、轻量圆角卡片、简短标题，按内容区分简报、任务状态、审批和文稿。适配系统返回、键盘遮挡、安全区域和字体放大；深色模式另行适配与验收。

### 5.1 为 iOS 与鸿蒙迁移保留的产品约定

- 三端使用同一账号、云端任务 ID、记忆、成果和权限模型；新增客户端无需搬迁云端数据。
- Rust 后端通过版本化接口与事件协议服务手机端；共享的是业务协议、数据格式和验收规则，前后端分别维护 Rust 与 TypeScript 实现。
- 核心页面与流程保持一致，系统返回、授权弹窗、分享和通知按各平台规范适配。
- 按能力显示入口；某个平台不支持的健康数据、录音方式或通知方式提供替代流程。
- 登录、购买、推送和文件分享均可更换平台实现，业务流程不绑定某个应用商店或 Google 服务。
- 本期只交付 Android；iOS/鸿蒙只做必要的架构验证和兼容性记录，不并行建设完整产品。

## 6. 关键功能的拟建规格

### 6.1 对话、任务与成果（F03、F06、F09、F10）

- 对话可直接发起任务；简单回答即刻返回，长任务生成可追踪记录。
- 支持用户主动录制短语音后转写、选择图片/文件和通过系统分享导入链接；首次使用相关能力时再申请权限。
- 任务展示当前步骤、已完成内容、遇到的阻碍与交付物。支持用户中途补充要求、停止任务。
- 搜索型结果附来源与抓取时间；重要事实缺少证据时明确标记。
- 首版交付 Markdown/HTML 报告和可下载附件；后续补充 PDF、DOCX、XLSX 等输出。
- 成果与任务保留关联，可从结果继续追问或发起下一步，支持手机内预览、下载及系统分享。

### 6.2 记忆（F04、F19）

- 将用户偏好、人物关系、项目状态和明确承诺保存为可读条目，记录来源、时间与适用范围。
- 用户可修改、删除、暂停记忆，也可选择某次对话不参与长期记忆。
- “我以前喜欢 A，现在改成 B”更新当前偏好，同时保留必要的变更说明。
- 当前消息、明确的用户修正和可靠的新资料优先于旧推断；有冲突时询问或保留不确定性。
- 删除记忆后不再用于新回答；是否同时删除原始会话或文件由用户单独选择，界面解释清楚。

### 6.3 每日首页与主动帮助（F02、F05、F17）

- 首版生成晨间简报、晚间回顾，以及日历变化/临近截止两类建议。
- 每条建议说明「为什么现在提示」「参考了什么」「可以做什么」。
- 支持忽略、延后、关闭同类提醒、设置静默时段；无重要变化时不重复通知。
- 生成建议与发送通知分别控制，App 内可查看的结果无需一定触发系统推送；通知权限关闭时仍保留结果。
- 数据尚未同步、权限失效或事实不完整时，显示缺失状态。

### 6.4 自动化（F07）

- 自然语言创建一次性或周期任务，保存前展示执行内容、时间、时区、连接器与预计用量。
- 支持编辑、暂停、恢复、删除，显示下次运行时间与历史结果。
- App 退出、进程被回收或手机离线后，已提交的云端任务继续；本地尚未上传的录音/文件显示待上传，不能提前标为已交给云端。
- 重新打开 App 时恢复任务进度与未读结果；弱网、上传中断和重复点击不会重复创建任务。
- 执行失败时给出原因和下一步；动作结果不明确时标为待核实，避免重复执行。

### 6.5 连接器与外部动作（F08、F19）

- 先申请完成当前任务需要的权限；未连接服务也可正常聊天、上传资料和管理记忆。
- 首版读取邮件、日历和选定文件，支持日历事件的预览与确认写入。
- 邮件先支持生成草稿；真正发送安排在后续阶段，提供收件人、正文和附件的确认预览。
- 准备写入前展示具体改动，确认与该版本内容绑定；内容变了则再次确认。
- 断开连接后停止新调用与同步。保留或删除已导入资料由独立选项控制。

### 6.6 手机录音、云端执行与技能（F11～F14）

- P0 支持短语音输入；P1 增加长录音/音频导入、转写、会议摘要和追问。录音须由用户启动，保存进度与状态可见。
- 锁屏、切到后台和来电中断的录音行为分别验收；不默认能够采集任意通话或其他应用的系统音频。
- 云端浏览器可在后续通过 Android App 查看进度、成果和停止执行；需要额外登录时由用户完成授权。
- F12 中的桌面控制和任意手机应用控制不纳入本期；未来 iOS/鸿蒙优先迁移助手本身及云端状态。
- Skills 首先提供官方维护模板；模板声明所需工具和权限，安装不自动扩大访问范围。
- 社区上传、分发、版本升级和审核放在后续阶段建设。

### 6.7 健康、财务等生活场景（F15、F16）

首版可用手动输入和手机上传资料实现饮食偏好、旅行、学习、收据整理等模板。Android 健康平台、可穿戴设备适配、账单规则和长期趋势分析分期推进；健康接入通过独立接口，后续分别对接 iOS 与鸿蒙的可用能力。财务模块以资料整理、预算和提醒为范围，直接银行交易另立项目。

Today 隐私政策说明 HealthKit / Health Connect 的健康数据接入为授权读取、不回写；撤销权限与删除已同步数据分别处理。我们的原生健康接入也按这一边界设计。[隐私政策](https://today.ai/privacy)

## 8. 六条端到端验收场景

| 场景 | 示例输入 | 通过标准 |

## 9. 如何判断“几乎一致”

对齐验收以**功能、流程、界面和平台**分别检查：

- **功能**：上述功能编号有可运行实现，并记录权限、平台和套餐条件。
- **流程**：首次设置、日常查看、任务执行、确认、失败恢复、删除撤权均走通。
- **界面**：以真实 Android 页面为主要参考，逐页对照空状态、加载、错误、长内容、键盘和系统返回。
- **平台**：本期以 Android 真机为验收对象；iOS/鸿蒙验证接口与适配边界，正式迁移时单独验收。

在完成登录后实测前，本稿能定义功能和架构基线，不能声称已覆盖 Today 当前所有界面细节与隐藏能力。
