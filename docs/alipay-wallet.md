# 支付宝用户钱包与付款

这是用户付款接入，不是妥啦商户收款。公开支付 MCP 的商户私钥不能代替用户授权，也不能用于查询用户全部历史账单。

## 当前交付范围

- 手机：连接状态、官方授权页面、绑定指令提交、真实授权校验、管理授权、逐笔付款确认、付款结果查询、本月和全部妥啦交易记录。
- Agent：`alipay_wallet_status`、`prepare_alipay_payment`、`get_alipay_payment`、`list_alipay_transactions`。没有绑定、确认或扣款工具。金额、商家与收银台材料必须来自真实订单，不能凭模型猜测。
- Rust：本人归属、加密存储、一次性确认凭证、订单去重、超时未知状态及查询恢复。确认后的同一请求不会再次执行付款；改换 Agent 操作序号也不会重新提交同一收银台订单。
- 账单范围为经妥啦发起并记录的交易。只有官方结果明确成功且金额匹配才进入“已核实付款”合计；全部历史账单、退款流水、余额和花呗未接入。

## 可用性边界

手机多人正式 Agent Pay 尚需企业主体和支付宝定向开通。当前未获得该通道，默认保持 `not_configured`。页面不能显示“已接入多人支付”，也不能把单机 CLI 改写 HOME 后当作多租户 SDK。

可选的自建适配器运行官方 `alipay-bot` 0.4.9，**仅支持一个真实、专用 Linux OS 账户对应一个指定妥啦用户**。它适用于独立自建实例的验证，不会自动成为官方多人服务器的付款通道。Linux amd64 以外的平台及官方多用户移动 SDK 需要单独适配。

这个适配器会检查真实 OS home 的所属 UID、0700 权限、非 root 身份、不可换绑的所有者标记、固定可执行文件 SHA256。数据库再次固定 owner；其他妥啦账号不能申请、绑定、使用或查询该钱包。进程使用参数数组而非 shell，并通过内核文件锁串行访问该 profile。更换数据库不解除 profile 的所有者约束。

## 独立实例安装

先准备真实、专用的非 root Linux 服务账户及 0700 home；home 必须与 `/etc/passwd` 登记一致。Node.js 是官方安全组件可能使用的运行依赖，`flock` 必须位于 `/usr/bin/flock`。不要复用已有个人 CLI 钱包 profile。仅用于可信的专用主机；CLI 会用命令参数传递绑定指令与收银台材料，主机管理员及能读取进程参数的本地用户可能看到它们，不支持与不可信 OS 用户共享主机。

在该账户下安装公开发布组件（安装脚本不执行组件、不申请钱包、不绑定或付款）：

```sh
python3 scripts/Install-AlipayWalletRuntime.py \
  --directory /opt/tada-alipay-runtime \
  --owner-id '<实际登录妥啦用户的 user_id>'
```

所有包只来自官方 HTTPS 下载地址，先校验完整归档 SHA256 再写入；不会改变全局 npm、PATH 或注册系统守护程序。不覆盖不一致的已有文件；旧 profile 或其他所有者标记将阻止安装。

服务进程需要在上述真实 OS 账户下运行，环境设置如下。owner/runtime 不属于普通后台可修改的设置，变更需要重启并核对运行身份。

```dotenv
ALIPAY_WALLET_RUNTIME=official_cli_single_user
ALIPAY_WALLET_OWNER_ID=<同一妥啦用户的 user_id>
ALIPAY_WALLET_CLI=/opt/tada-alipay-runtime/alipay-bot
CONNECTOR_ENCRYPTION_KEY=<部署原有的32字节加密密钥，不要换掉已有密钥>
```

缺少任一配置、profile 不符合身份要求或程序 hash 不匹配，保持不可用；普通 `ALIPAY_WALLET_ENABLED=true` 和商户 APPID 不能绕过该校验。生产主机安全组件兼容性还必须通过手机里的“检查授权状态”实际验证。

用户在手机“能力 → 支付宝”发起连接，打开官方页面亲自授权，并按官方页面要求提交绑定指令；指令仅经当前请求传给官方组件，不进入数据库、模型上下文或日志。管理授权只是打开支付宝管理页面，尚不能声称远端已撤销；用户操作后要再次核实状态。

## 资金与数据

待确认订单 10 分钟失效，确认凭证只给当前用户手机 API，Agent 不可获得。官方请求超时或结果无法核实时记为 `unknown_outcome`；没有本次官方输出的查询凭证则不查询或补造凭证。禁止从调试日志中取授权链接、查询凭证或付款证明。

SQL 中订单内容、收银台链接、授权链接、确认凭证与查询凭证以原有 CONNECTOR_ENCRYPTION_KEY 进行 AES-GCM 加密，AAD 绑定用户和用途。绑定码不保存。CLI 自己管理的安全凭证仍由该专用 OS profile 和支付宝安全组件管理，不能声称这些文件也由本数据库加密；备份、迁移与注销必须单独核对。

交易合计覆盖当前筛选区间，而非仅当前页。超过 10,000 条扫描上限会返回 `totals_complete=false`，需要缩小时间范围。已支付、未知或正在处理的订单不会因取消按钮而被标成退款或未付款。

## 正式多人移动接入仍需完成

1. 通过支付宝 Agent Pay 联系渠道申请企业智能体接入，确认妥啦场景及各用户授权契约。
2. 获得正式 SDK/身份参数后新增独立的移动端 provider，不能把此单用户 profile 放大为共享钱包。
3. 完成两个真实独立账号的绑定、撤权、账号切换、跨用户拒绝、单笔确认、支付回执、失败恢复与金额核验。
4. 真实绑定与付款由用户在官方页面完成；未完成这些验收前不对外开放真实多人扣款。

目前的隔离 CLI 探测和自动化测试不等于真实支付成功。本阶段没有替任何用户授权钱包或发起真实扣款。

## 本地验证与未完成事项（2026-11-03）

- Rust 钱包：16 项测试通过，含并发 API 实例去重、只执行一次付款、未知结果恢复、跨用户拒绝、加密、金额不符、授权中刷新与绑定、未绑定拒绝付款。
- 通用 MCP 隔离回归：3 项通过；支付宝不能经通用 MCP 或普通设置绕过专用通道。
- Rust Agent 工具：1 项测试通过，覆盖代确认、伪造 owner、绑定指令与越界分页参数拒绝。
- 手机 TypeScript 检查通过；5 个相关 Jest 套件、55 项测试通过。覆盖实际 React 组件的逐笔确认、连点、仅查询恢复、绑定指令清理、切换 API 清空旧资料和支付宝搜索。
- 安装脚本：4 项离线测试通过，验证归档校验失败无写入、不覆盖未知程序、只解压白名单、版本不符拒绝和根目录拒绝。
- 官方 Linux amd64 0.4.9 可执行文件及帮助命令已在临时容器中实际启动。完整原生辅助文件齐全时，`check-wallet --json` 返回 `code=500`、`查询失败`、`当前安全环境存在问题`。该探测关闭了容器网络，因此不能据此认定云主机同样不兼容，也不能证明它已经可用于钱包绑定。需要在符合官方要求的真实 Linux 安全环境另行验收。
- 将隔离容器改为真实登记的非 root `node` 用户及其 0700 home 后，同一检查返回 `code=500`、`查询失败`、`系统暂时繁忙`。网络仍明确关闭；这次仅验证原生组件可加载并返回业务错误，没有执行开通或付款命令。

以上是 Windows Rust/React 测试与隔离 Linux CLI 探测，不是 Android 真机付款、生产 Linux 服务集成或真实支付宝支付验收。没有部署、开通钱包、发送绑定指令或执行真实扣款，也未发布 APK。本次保留共享目录中其他开发会话的代码；正式多人移动支付仍需官方资格、SDK 配置及完整验收。

申请时可以提交：妥啦是 Android 个人 AI 助手，希望用户分别授权本人支付宝，Agent 从合作应用取得真实订单后，展示商家、金额与商品，经用户逐笔确认完成支付，并查询该笔交易结果。申请入口：[支付宝合作意向](https://aipay.alipay.com/merchant-intent)。全量个人账单读取需单独向支付宝确认权限，不能从支付资格推定已具备。
