# DeepSeek 联网搜索与网页读取

Pi 服务向模型提供 `web_search` 和 `web_fetch` 两个只读工具，分别调用 DeepSeek 官方 Search / Fetch API。Rust 继续负责账号、执行权限、业务工具和执行记录；APK 不持有搜索密钥，也不直接请求搜索供应商。现有手机聊天协议不变。

官方接口与认证说明：[DeepSeek Search & Fetch](https://api-docs.deepseek.com/guides/search/)。这两个接口不等同于聊天模型自动联网：Pi 必须实际执行工具，再将结果交给模型继续回答。

## 服务端配置

| 变量 | 作用 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 默认复用已有 DeepSeek 密钥；来自受保护的后台配置快照或旧部署的 Pi 环境 |
| `DEEPSEEK_SEARCH_API_KEY` | 可选，单独配置搜索密钥时优先使用；不会借用 `MODEL_API_KEY` |
| `DEEPSEEK_WEB_ENABLED` | 默认有 DeepSeek 密钥时启用；`false` 关闭；`true` 要求有密钥，否则新执行返回配置错误，服务仍可启动 |
| `AGENT_MAX_WEB_SEARCHES` | 每次执行最多搜索次数，默认 4，上限 8 |
| `AGENT_MAX_WEB_FETCHES` | 每次执行最多读取次数，默认 4，上限 8 |

请求固定发送到 `https://api.deepseek.com/v1/tools/search` 和 `/v1/tools/fetch`，不会跟随模型代理地址变化，也不跟随供应商接口的 HTTP 重定向。部署时只需在现有 Pi 服务构建目录更新代码并重启 Pi；无需新增 APK 权限或修改 Rust 数据库。启用后 Pi `/health` 返回 `web_search: true`。需要运行在 `AGENT_MODE=pi`，旧 direct 模式不使用此功能。

新部署设置 `TADA_RUNTIME_CONFIG=enabled` 后，从 Rust 管理后台读取生效配置。每轮固定一个版本，后台修改用于下一轮；缺失或读取失败不会回退旧环境 Key。详见 [运行配置](RUNTIME-CONFIG.md)。

## 行为与边界

- 每次搜索默认返回 5 条，最多 8 条；先给标题、摘要、URL 和可能的发布日期，再按需读取关键正文。每页正文最多 20,000 字符，截断会明确标记。
- 最新状态优先核查官方来源，模型需附来源链接及核实日期。抓取时间不等于公告生效时间；涉及基金限额要区分销售平台、份额类别、单日限制。公开网页搜索无法保证得到平台登录后的实时可购额度，查不到应说明。
- 外部正文作为不可信资料处理，不允许据此改变权限或执行数据写入；工具提示要求查询词去除私人资料和密钥。这是模型指令约束，并非语义脱敏器，不应主动把私人附件送入搜索。
- 每次付费 API 请求前检查 Rust 执行权限；请求受本轮取消、15 秒超时和总步骤限制约束。每轮独立计数，失败请求也消耗本地调用次数，不自动重试。
- 仅支持公开 HTTP(S) 网站，拒绝 IP、内网主机名、非标准端口和 URL 内嵌凭据；目标解析和重定向另受 DeepSeek 的安全策略约束。接口不能登录、提交表单或读取本机文件。
- 供应商响应最多读取 2 MiB；错误只返回安全的原因，不透传供应商错误正文或网络异常，以免泄露密钥。
- 运行用量新增 `web_search_requests` / `web_fetch_requests`，表示出站尝试次数，不代表供应商账单中的成功计费次数。成功结束时同时写入 `finished` 事件。保留现有执行日志中的工具名、参数和成功/失败；密钥不进入模型上下文。
- 当前调用次数限制按单次执行隔离，没有新增账号日预算或跨实例金额预占。真实费用以供应商账单为准。

## 验证与发布状态

`pnpm test` 包含模拟供应商 HTTP 的工具测试，以及真实 Pi 循环中“搜索 → 读取公告 → 回答”的集成测试，覆盖密钥隔离、调用上限、取消、错误及参数验证。测试不用真实密钥，不产生供应商费用；它们不证明真实搜索覆盖率或模型对具体投资问题的正确率。

本次改动先在本地完成。云端需与正在进行的其他后端改动一起构建发布，发布后再做受控的真实查询验收；不要仅依据本地测试认定手机云端已经启用。
