# DeepSeek 联网搜索与网页读取

Pi 服务向模型提供 `web_search` 和 `web_fetch` 两个只读联网工具，分别调用 DeepSeek 官方 Search / Fetch API；另有本地 `research_plan`、`research_review` 整理调查清单和检查已读证据。Rust 继续负责账号、执行权限、业务工具和执行记录；APK 不持有搜索密钥，也不直接请求搜索供应商。现有手机聊天协议不变。

官方接口与认证说明：[DeepSeek Search & Fetch](https://api-docs.deepseek.com/guides/search/)。这两个接口不等同于聊天模型自动联网：Pi 必须实际执行工具，再将结果交给模型继续回答。

## 服务端配置

| 变量 | 作用 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 默认复用已有 DeepSeek 密钥；来自受保护的后台配置快照或旧部署的 Pi 环境 |
| `DEEPSEEK_SEARCH_API_KEY` | 可选，单独配置搜索密钥时优先使用；不会借用 `MODEL_API_KEY` |
| `DEEPSEEK_WEB_ENABLED` | 默认有 DeepSeek 密钥时启用；`false` 关闭；`true` 要求有密钥，否则新执行返回配置错误，服务仍可启动 |
| `AGENT_MAX_WEB_SEARCHES` | 每次执行最多搜索次数，默认 100，上限 100 |
| `AGENT_MAX_WEB_FETCHES` | 每次执行最多读取次数，默认 100，上限 100 |
| `AGENT_RESEARCH_REVIEW_ENABLED` | 实验性调查完成检查；默认关闭，仅显式 `true` 启用。部署环境变量修改后需重启 Agent，不属于模型密钥配置 |

请求固定发送到 `https://api.deepseek.com/v1/tools/search` 和 `/v1/tools/fetch`，不会跟随模型代理地址变化，也不跟随供应商接口的 HTTP 重定向。启用后 Pi `/health` 返回 `web_search: true`。需要运行在 `AGENT_MODE=pi`，旧 direct 模式不使用此功能。100 次研究预算需要同步部署 Pi、Rust 配置校验及长执行时限，并使用支持长连接的 APK；只更新其中一层仍可能被旧的工具、轮次或时间限制提前中断。现有明确保存的更小后台值仍生效，升级不会静默覆盖管理员设置。

新部署设置 `TADA_RUNTIME_CONFIG=enabled` 后，从 Rust 管理后台读取生效配置。每轮固定一个版本，后台修改用于下一轮；缺失或读取失败不会回退旧环境 Key。详见 [运行配置](RUNTIME-CONFIG.md)。

## 行为与边界

- 每次搜索默认返回 5 条，最多 8 条；先给标题、摘要、URL、`source_id` 和可能的发布日期，再读取关键正文。正文默认取 8,000 字符，`find` 定位默认取 4,000，单次最多 20,000；支持 `offset`/`length` 续读和 `find` 定位关键词，返回 `next_offset`、总长度和截断标记。正文附 `[p编号]`，检查可直接引用 `passage_id`，避免重写引文和重复校验。`characters` 为原文字符数，不包含编号。缓存命中不额外出站计费，但每次读取仍检查运行权限。缓存和已读证据分别按正文计限 400,000 字符，段落索引随证据淘汰，不跨执行保留；淘汰的段落编号不可再用于检查，须重读。
- 100 次搜索和 100 次网页读取是独立的单轮上限，不要求每次回答用满；新执行重新计数。模型初始提示给出两项额度，每次成功工具结果中的 `web_budget` 给出已用、上限和剩余次数。达到上限时分别说明“搜索”或“网页读取”及已用/上限，不将本轮限制误称为余额或每日额度。
- 默认总工具预算为 240 次、模型轮次 256、总执行时间 20 分钟；仍保留单次请求 15 秒时限和固定大小的响应/正文边界。慢网站、取消、时间耗尽或模型上下文容量仍可能使执行少于 100 次；100 是许可上限，不保证 100 份最大正文一定能在模型上下文内同时保留。
- 同一模型轮次的独立联网请求可以并行，每个执行最多 3 个出站请求；等待期间取消的请求不出站、不预扣出站次数。业务工具和研究检查工具仍明确串行，混合批次由 Pi 整批串行执行，避免改变业务写入顺序。
- 在模型轮次边界，若已有候选来源且自上次读取以来已尝试 3 次搜索，会暂时从下一轮工具目录移除 `web_search`，先让模型读取已找到的资料；尝试 `web_fetch` 后恢复，读取失败也允许继续找替代来源。没有候选或读取预算已经耗尽时不触发此调度。一个已经发出的多搜索批次不会被中途拆断，这不是新增的搜索次数上限。该策略只调整联网工具，不移除原有业务工具。
- 最新状态优先核查官方来源，模型需附来源链接及核实日期。抓取时间不等于公告生效时间；涉及基金限额要区分销售平台、份额类别、单日限制。公开网页搜索无法保证得到平台登录后的实时可购额度，查不到应说明。
- 外部正文作为不可信资料处理，不允许据此改变权限或执行数据写入；工具提示要求查询词去除私人资料和密钥。这是模型指令约束，并非语义脱敏器，不应主动把私人附件送入搜索。
- 每次付费 API 请求前检查 Rust 执行权限；请求受本轮取消、15 秒超时和总步骤限制约束。每轮独立计数，失败请求也消耗本地调用次数，不自动重试。
- 仅支持公开 HTTP(S) 网站，拒绝 IP、内网主机名、非标准端口和 URL 内嵌凭据；目标解析和重定向另受 DeepSeek 的安全策略约束。接口不能登录、提交表单或读取本机文件。
- 供应商响应最多读取 2 MiB；错误只返回安全的原因，不透传供应商错误正文或网络异常，以免泄露密钥。
- 运行用量中的 `web_search_requests` / `web_fetch_requests` 表示出站尝试次数，不代表供应商账单中的成功计费次数。成功结束时同时写入 `finished` 事件。工具事件增加 `research` 元数据：去除常见敏感标识后的搜索词、来源编号、来源地址的 origin/path、可能的发布日期、正文长度、偏移和检查状态。不记录模型推理、供应商正文、请求头或业务工具的原始参数；URL 查询参数不会进入审计。常见手机号/邮箱/密钥模式过滤并不等于完整语义脱敏，不应主动搜索私人内容。
- 当前调用次数限制按单次执行隔离，没有新增账号日预算或跨实例金额预占。真实费用以供应商账单为准。

## 验证与发布状态

### 调查完成检查（2026-11-01）

**统一发布边界：此强制调查循环尚未通过完整真实模型质量验收，默认不启用。** 默认保留常规 `web_search` / `web_fetch`、100 次独立额度与真实流式回答；不会因为未调用实验性检查工具而隐藏或拒绝常规联网答案。仅部署者显式设置 `AGENT_RESEARCH_REVIEW_ENABLED=true` 后，才加入调查清单、检查工具、动态搜索调度与强制完成检查。该开关不改变用户权限、密钥来源或原有调用预算。以下完成检查行为均指显式启用实验功能之后。

- 明确的公开调查问题会启动检查；其他请求只要实际使用联网工具也会启动。意图判断是保守规则，不会为了查询已保存记忆、附件或本机资料强制联网；普通聊天继续直接流式输出。
- 调查清单限 1–8 个问题，检查结果最多 24 项，同一问题可以按候选、渠道和条件拆成多项；必须覆盖每个问题。`supported` 项引用实际由 `web_fetch` 交给模型的 `source_id`/`passage_id`，程序提取对应原文；兼容直接提交 12–240 字的原文 `quote`。搜索摘要、未读取的网页、编造或已淘汰的编号不能作为正文证据。`uncertain` 项必须说明未核实原因。使用稳定的 `question_id` 关联问题，兼容原文中的换行、全角字符及空白，不接受改写或拼接的引文。
- 已取得搜索来源但从未尝试读正文时不能结束检查。读取失败允许保留未核实项，不要求无限重试。已发现的矛盾要列出；标记解决时须引用双方已读正文。继续搜索、读取或更改清单后，上次检查失效。
- 一次检查集中返回缺少正文或引文不匹配的来源编号，便于批量补查，避免每修正一个来源就重做整份检查。重新检查失败（包括工具参数不合法）会撤销旧的通过状态，不能沿用旧状态发布新草稿。
- 这是一道程序检查，只校验清单覆盖和引文是否来自已读片段，**不自动证明结论与引文的语义关系、不自动认证官网身份、不保证发现所有矛盾或拿到最新公告**。时效性、相关性及后续公告仍由模型继续调查；不能把检查通过包装成平台对答案真实性的认证。
- 模型指令要求第三方汇总只用于发现候选，现行可执行条件要逐项读原公告；直销/代销上限或 A/C 类别分别列出不代表允许相加。检查结果返回来源的检索发布日期与实际抓取时间，提醒模型保留适用时点。这里的“优先原始公告”和语义相关性仍属于模型判断，没有伪装成程序已经认证来源或限额。
- 调查未通过时，模型直接结束会触发最多两次补查提醒；仍拒绝核查则返回 `research_incomplete`，不会把未核验草稿作为最终答案发布。已有工具、时间、轮次预算照常生效；修正提醒明确禁止重复执行已成功的业务操作。
- 调查草稿不推送到用户界面。通过检查后，下一次模型回答仍使用真正的上游文字增量，不做全文完成后的打字动画。传输文本轮次按实际可见回答计数，避免多轮调查尚未答复就超过 Rust 的文本轮次边界。
- 手机依据实际工具事件显示“整理调查清单”“核对搜索结果”“比对日期和条件”“核对来源与未确认事项”；不展示内心推理。详细查询及来源元数据保留在服务端 Agent 执行记录，尚未新增完整的客户端来源时间线。

`pnpm test` 包含模拟供应商 HTTP 的工具测试，以及真实 Pi 循环中“计划 → 搜索 → 读取公告 → 检查 → 回答”和 100 次搜索加 100 次读取的集成测试，覆盖第 101 次拦截、独立额度、并发预留、缓存分页、密钥隔离、取消、错误、摘要冒充原文、伪造引文、清单遗漏、冲突双方证据、未核验草稿拦截与修正次数边界。自动测试不用真实密钥，不产生供应商费用；它们不证明真实搜索覆盖率或模型对具体投资问题的正确率。

2026-11-01 本地 TypeScript 编译和 94 项 Agent 测试通过；手机流式控制器的 2 个相关测试套件、15 项测试通过，包含断线重连后恢复实际调查阶段。Agent 回归包含真实 Pi 循环中的动态工具目录变化、读取后恢复搜索、批量列出证据缺口及失败后不能复用旧检查状态。修复了日志超时测试的 35ms 调度竞争：使用受控时钟在目标请求开始后验证中断，不改变生产执行时限。复用已有依赖，没有安装新依赖或构建原生 APK/Rust。

### 统一发布补充验收（2026-11-01）

默认关闭强制调查循环后的 TypeScript 编译和 96 项 Agent 回归通过，实验模式的既有回归显式开启检查，不会因默认关闭而失去覆盖。新增默认路径回归实际执行搜索与网页读取，确认不暴露实验工具、不隐藏回答，也不要求先通过检查。

另以当前配置的真实 DeepSeek Flash 做了两次小范围合成联网冒烟，无生产对话、数据或配置写入：一例自动寻找 Rust/Node.js 官方资料，约 14.3 秒结束、首段真实文字约 0.9 秒，Rust 版本因选择首页而明确未核实；一例直接提供两条官方 URL，约 12.2 秒结束、首段约 0.75 秒，读出 Rust 1.99.1 与 Node.js v26 LTS，主结论与独立读取的官方页面一致。两例均使用关闭思考档位，不是 max 档位的复杂研究质量测试，也不能与前述复杂基金问题直接比较速度。
